# WireGuide Plus

**マルチトンネルとネットワーク認識型自動化を備えた WireGuard クライアント**

WireGuide Plus はオープンソースプロジェクト
[`korjwl1/wireguide`](https://github.com/korjwl1/wireguide) を**深く修正・強化した**
フォークです。2つの核となる機能:

- **マルチトンネル同時接続** — 複数の WireGuard トンネルを同時に確立し、互いに
  干渉することなく独立して動作します;
- **条件付き自動接続** — Wi-Fi SSID・時間帯・システム起動などの条件に基づいて
  適切なトンネルを自動接続します（例: オフィスの Wi-Fi ではトンネル A、自宅では
  トンネル B）。

[English](README.md) | [简体中文](README.zh.md) | [繁體中文](README.zh-TW.md) | [한국어](README.ko.md) | **日本語**

> **Windows 10 / 11（x64、x86 32ビットおよび ARM64）と macOS（Apple Silicon / arm64）を完全サポート**しています —
> macOS は Apple Silicon 実機で十分に検証済みです。Linux（x64、arm64）は**実験的プレビュー**として提供 —
> CI でビルドされますが実機でのテストは未実施です（[プラットフォームサポート](#プラットフォームサポート) を参照）。
> **Android / iOS は非対応です。**

## 機能

- **マルチトンネル同時接続** — 一度に1本しか接続できないアップストリームとは異なり、
  複数のトンネルを並行して実行できます — 社内ネットワークと出口ネットワークへ同時に
  アクセスしたい場合に最適です。
- **条件付き自動接続** — Wi-Fi SSID / 時間帯 / システム起動をトリガーに、トンネルを
  自動で接続・切断します。ルールは優先度と排他（相互排除）をサポートします。
- **自動再接続** — 予期しない切断後もトンネルが自動復旧し、接続状態がリアルタイムに
  表示されます。
- **画面オフ・ロック・スリープ中も接続を維持** — 設定（既定でオン、トンネル単位で上書き可）
  により、画面オフ・スクリーンセーバー・ロックを越えてトンネルを維持し、スリープから
  復帰すると自動で再接続します。
- **ログイン時自動起動** — ログイン後に WireGuide Plus を起動し、ルールに従って接続する
  設定（「最小化で起動」と組み合わせれば、起動直後にウィンドウをたたんだ状態にできます）。
- **最小化で起動** — Windows では起動時にタスクバーへ最小化します（タスクバーのアイコンは
  残るので、メインウィンドウはいつでも開き直せます）。macOS / Linux ではシステムトレイへ
  最小化されます。
- **トレイ接続通知** — 起動10秒後（昇格プロンプトの確定後）に現在の接続状態を表示します。
  ネットワーク変更（Wi-Fi 切替・ケーブル抜去・ネットワーク喪失など）でトンネル状態が
  変わった場合も、10秒遅延で安定した最新状態のバブルを表示します。バブルにはアクション
  メニュー（メインウィンドウを開く / 切断）があり、手動で閉じるか、設定可能な表示時間
  （既定10秒、設定で変更可）で自動的に閉じます。macOS と Linux も同じバブルを表示するようになりました（以前は Windows のみ）。
- **トンネル管理** — `.conf` のインポート / エクスポート、接続履歴、クイック切り替え。
- **AmneziaWG（AWG）トンネル** — AmneziaWG（難読化 WireGuard）設定のインポート・接続に対応。AWG は設定内の Jc/Jmin/Jmax/S1-S4/H1-H4 難読化パラメータから自動検出され、該当トンネルには「AmneziaWG」バッジが表示されます。設定 → 詳細でサポートを無効化できます。
- **トンネルエディター：フィールドビューとスクリプトフック** — conf テキストに加え、キーごとのフォーム（interface / peer グループ）で設定を編集でき、PreUp / PostUp / PreDown / PostDown スクリプトフックを管理（ファイル選択・空作成・コード編集・クリア）できます。接続中でも編集でき、保存すると切断して変更を適用し、自動で再接続します。
- **トンネルごとの物理出口バインディング** — 「インターフェース固定」有効時、トンネルごとに暗号化トラフィックを特定の物理 NIC に固定（Windows / Linux / macOS）。バインドした NIC が消えた場合はダイアログで待機・自動切替・手動指定を選択できます。
- **設定のエクスポート/インポート** — tunnels・scripts・`config.json`（ログを除く）を 1 つのアーカイブにまとめ、別マシンへの移行が簡単に。
- **ツールタブ** — 組み込みの **DNS リークテスト** でトラフィックが本当に設定した DNS サーバーから出ているかを確認でき、 **ルート可視化** は現在のルーティングテーブルを表示し、各ルートに VPN / Direct バッジを付け、LAN オンリンクフィルターとセルラーインターフェイス表記に対応します。
- **トンネルポリシー** — トンネルごとの DNS 解決パス、特定ドメインのトンネル強制通過、トラフィック保護、デフォルト DNS、および決定的な競合解決。
- **遅延プローブ** — トンネルごとの遅延プローブが複数ターゲットの並行に対応。各候補（公共リゾルバ 8.8.8.8 / 223.5.5.5、トンネルエンドポイント、任意の手動アドレスまたはドメイン）を同時にプローブし、解決 IP・種別・往復時間を表示します。分割トンネルでは手動ターゲットは保存前にトンネルの AllowedIPs カバレッジで検証されます。対象は保存後に即座に再プローブされ、ドメインのエンドポイントは詳細ページ上部に現在の解決アドレスを表示します。

   修正しました（現在は `goversioninfo` で生成）。
4. **安定性の修正** — 更新確認スケジューラの重複排除、物理アダプター検出の精度向上など
   （[CHANGELOG](CHANGELOG.ja.md) を参照）。

1. **SSID ドロップダウン** — 自動接続ルールで、システムが保存している**すべての

   GitHub に到達できない / レート制限されることによる更新失敗を解決します。

4. **システム統合** — ログイン時自動起動、最小化起動（Windows はタスクバー / macOS・
   Linux はトレイ）、トレイ接続通知（起動10秒後 / ネットワーク変更で接続状態が変わった
   ときに表示、既定10秒、変更可）。
5. **ウィンドウタイトルと操作感の改善** など。
6. **AmneziaWG（AWG）プロトコル対応** — DPI 耐性のある難読化トンネル AmneziaWG 用の amneziawg-go ベースのプロトコルバックエンドを追加。設定の自動検出、UI バッジ表示、設定 → 詳細でのオプトアウトに対応。

## 自動化ルール

自動化設定は**トンネルごと**に独立しています（任意のトンネルの `…` メニュー →「自動化…」）。各トンネルがそれぞれ専用のルールセットを持つため、「会社 Wi-Fi では仕事用 VPN を接続、同 Wi-Fi では個人 VPN を切断、自宅では個人 VPN を接続」といった組み合わせが互いに干渉せず共存できます。

エディタ上部のライブネットワークパネルは**現在のトンネル**の環境だけを表示します。物理ハードウェアインターフェース（`in use` / `not in use` を表示）、Wi-Fi SSID、ゲートウェイ MAC、ゲートウェイ IP、サブネットを各 1 行で示し、このトンネルの条件がどの値に一致したかも表示します。仮想アダプタは除外され、Wi-Fi 未接続時は SSID に「Wi-Fi 未接続」と表示されます。パネルとルール説明は折りたたみ可能で、エディタ全体をスクロールできます。

「インターフェース固定」はすべてのデスクトッププラットフォームで対応しました：Windows は `IP_UNICAST_IF` でトンネルの UDP ソケットを指定 NIC にバインドし、Linux は `ip route … dev <iface>` のバイパスルートを、macOS は `-ifscope` 付きのバイパスルートを使用します。物理出口の指定は OS のルーティングポリシー（WireGuard プロトコル設定ではない）であり、バインドした NIC が消えた場合はダイアログで待機・自動切替・手動指定を選択できます。

### ルールロジック

- 1 つのトンネルのルールは**ひとつの順序付きリスト**であり、上から下へ評価されます——**ルールの位置がそのまま優先度**です。接続ルールと切断ルールはリスト全体で自由に混在でき、ドラッグで並べ替えられます。
- **最初にマッチしたものが勝ち（ルール内は AND）**：1 ルール内のすべての条件が揃って初めてそのルールは発火しますが、リスト全体で**最初にマッチした 1 ルール**だけが実際に動作を実行します。マッチしたルールより後ろのルールは「マッチはしたが優先度で負けた（deprioritized）」となり実行されないため、同じ SSID に対して切断と接続が同時に実行される矛盾は起こりません。
- **デフォルト状態への収束**：**どのルールにも一致しない**場合、トンネルは**デフォルト状態**（接続または切断——自動化エディタの上部で選択）に収束します。ルールもデフォルト状態も設定されていないトンネルに自動化は干渉しません。デフォルト状態のみを設定した場合（ルール 0 件）、トンネルは常にそのデフォルト状態に収束します。
- **編集画面のライブマッチインジケーター**：自動化エディタを開いている間、各条件が現在のネットワークに一致しているかどうかがその場で表示され、実際に有効な最初のマッチルールは「in use（使用中）」としてハイライトされます。最上部の判定バーにはそのトンネルの最終的な決定が表示されます。編集のたびにインジケーターは即座に再評価され（約 250 ms のデバウンスで IPC 経由）、バックグラウンド helper が実際に規則を実行するのと**まったく同じ**エンジンを使うため、UI 表示と実際の動作は常に一致します。同エンジンはコマンドライン（`wireguideplus automation`）からも利用でき、CUI 環境での確認に便利です。

### 手動オーバーライド

トンネル詳細ビューの **接続** / **切断** ボタンは手動制御です。手動接続は **接続を強制しすべての自動化ルールを無視** し、手動切断は **切断を強制しすべての自動化ルールを無視** します —— 次に自動化がネットワークを再評価するまで。UI にはラッチインジケーターがあり、現在のトンネル動作が手動オーバーライドによるものか自動化によるものかを示すため、何が接続を実際に動かしているかを常に把握できます。

### 自動化からトンネルを除外

手動オーバーライドはアプリの再起動までしか続きません。自動化に**決して**動かされたくないトンネル——典型的には別の WireGuard クライアントも同じトンネルを管理している場合——には、トンネルのポリシーパネルで「自動化から除外」を設定します。トンネルはルールとデフォルト状態を維持しますが、エンジンは接続も切断も行いません。

この除外はトンネル詳細ビューの上部にあるワンクリックの「自動化を停止」トグルでも行え、トンネルを見ているその場で自動化を抑制できます。新しいグローバルな「システムのスリープを防止」設定（既定オフ）はアプリ起動中に PC を起覚状態に保ち、アイドル/スリープの電源ポリシーがトンネルを静かに切るのを防ぎます。別のクライアントが既にトンネルのアドレスを占有している場合、WireGuide Plus は競合するソフトウェアを明示し「そのトンネルの自動接続を停止」を提案する対話型ダイアログを表示します——決定するのはあなた、他のクライアントを強制停止することはありません。

### 1 つのトンネルに 1 つのクライアント

2 つの WireGuard クライアントが同じトンネルを同時に実行することはできません。トンネルの `Address` は先着順でいずれかのアダプターが占有し、後から接続したクライアントはアドレス割り当ての段階で失敗します（Windows は `The object already exists.` を報告）。公式 WireGuard クライアントも併用している場合は、同じトンネルのサービスを先に停止してください（例: `Stop-Service 'WireGuardTunnel$<トンネル名>'`）。あるいはそのトンネルを自動化から除外します（上記）。WireGuide Plus は起動時にこの衝突を検出し、競合するアダプターの名前を helper ログに記録し、失敗した自動化接続をバックオフ付きで再試行します（30 秒 → 1 分 → 2 分 → 5 分。ポーリングのたびにアダプターに連続してぶつかることはありません）。

### 条件タイプ

| 条件 | 一致条件 | 典型的な用途 |
| --- | --- | --- |
| **SSID** | 現在の Wi-Fi の SSID 名と**バイト単位で完全一致**（大文字小文字を区別、途中の空白や特殊文字もすべて比較。802.11 の定義に準拠）。 | 「`会社 5GHz` に繋いだら仕事用 VPN を接続」。 |
| **サブネット（Subnet）** | 現在の物理 NIC の IP が、指定した CIDR 範囲（例: `192.168.178.0/24`）に含まれるか。 | 自宅/会社の LAN セグメントは既知だが SSID は一定でない場合。 |
| **ゲートウェイ MAC** | 現在のデフォルトゲートウェイ（ルーター）の MAC アドレス —— SSID やサブネットが一般的な名前でも、特定のネットワークを識別できます。 | 「カフェのルーターでは**絶対に**自動接続しない。」 |
| **ゲートウェイ IP** | 現在の物理ネットワークのデフォルトゲートウェイ IP。 | 会社中の SSID が全部同じだが階ごとにゲートウェイ IP が違う、といったケース。 |
| **インターフェース（Interface）** | 現在上り経路として使われているネットワークアダプタの名前。ドロップダウンには本機の**すべて**のネットワークアダプタ——有線・無線を問わず、さらに**未接続のアダプタ**も——が表示されるので、まだ挿していないドック / USB LAN / Thunderbolt アダプタ / Wi-Fi カード向けに事前にルールを書いておけます。 | 「会社のドックに繋いだ時の LAN アダプタを通っている時だけ仕事 VPN を接続」。 |
| **時間帯（Time window）** | 曜日の集合 + 開始 / 終了時刻（ローカル時計）。 | 「月〜金 09:00–18:00 の間、仕事用 VPN は常にオン。」 |

1 ルール内で上記を自由に組み合わせられます：例えば「SSID = 会社 AND 時間帯 = 月〜金 09–18」で 2 条件 AND の 1 ルールになります。各トンネルの disconnect / connect 両グループに、AND 条件からなるルールをいくつでも登録可能です。

## プラットフォームサポート

| プラットフォーム | 状態 |
| --- | --- |
| Windows 10 / 11（x64、x86 32ビット、ARM64） | ✅ 完全サポート（マルチトンネル同時接続 + SSID 自動接続、AmneziaWG 含む） |
| macOS（Apple Silicon / arm64） | ✅ 完全サポート — Apple Silicon 実機で十分に検証済み |
| Linux（x64、arm64） | 🚧 実験的 — CI でビルド済みだが実機テスト未実施 |
| Android / iOS | ❌ **非対応**（トンネルを同時に実行できず、Wi-Fi SSID による自動切替も不可） |

### モバイル版がない理由

本プロジェクトの核となる機能は**マルチトンネル同時接続**と**ルールベース自動接続
（例: Wi-Fi SSID による）**です。Android / iOS ではシステムカーネルと権限の制約により、
WireGuard 実装が**複数トンネルの同時実行**や**Wi-Fi SSID による自動切替**を行えません —
モバイルではどちらの核となる目標も達成できません。そのため本プロジェクトは**明示的に
モバイルを対象外**としています。モバイルユーザーは、単一トンネルの用途には公式 WireGuard
アプリのオンデマンド機能を利用してください。

## ダウンロードとインストール

各リリースでは対応プラットフォームごとに**インストーラー**（推奨）と**ポータブル版**を公開しています — お使いの OS を選んでください。macOS は `.dmg`/`.zip`、Linux は `.deb`/`.tar.gz`、Windows は以下のインストーラー/ポータブル版です。すべてのリリースには Ed25519 署名付きの `SHA256SUMS`（および `SHA256SUMS.sig`）も同梱され、アプリ内アップデーターは更新適用前に検証します。

### Windows

**インストーラー（推奨）**

- Windows x64 インストーラー: `wireguideplus-<version>-amd64-installer.exe`
- Windows x86（32ビット）インストーラー: `wireguideplus-<version>-x86-installer.exe`
- Windows ARM64 インストーラー: `wireguideplus-<version>-arm64-installer.exe`

インストーラー名にはバージョンとアーキテクチャが含まれます（`wireguideplus-<version>-<arch>-installer.exe`、
arch は `x86` / `amd64` / `arm64`）。インストールされるプログラムのファイル名にも
アーキテクチャが付きます（`wireguideplus-<arch>.exe` — ファイルのプロパティ → 詳細でも
表示されます）。64ビット版インストーラーは既定で `C:\Program Files\WireGuide Plus` に、32ビット版は
`C:\Program Files (x86)\WireGuide Plus`（32ビット OS では `C:\Program Files\WireGuide Plus`）
にインストールします。インストール先はインストール中に変更できます。スタートメニューの
ショートカット（「WireGuide Plus のアンインストール」を含む、既定オン・任意）と
デスクトップショートカット（常に作成）が登録されます。インストーラーには必要なファイル
がすべて含まれており、追加ダウンロードは不要です。

**ポータブル版（インストール不要）**

- `wireguideplus-amd64.exe` **+ `wintun-amd64.dll`**（32ビット exe は **`wintun-x86.dll`**、
  ARM64 exe は **`wintun-arm64.dll`**）— **同じアーキテクチャ**の2ファイルをまとめて
  ダウンロードし、同じフォルダーに置いてから exe を実行してください。

ポータブル版は**単体では動作しません**。WireGuard トンネルを作成するために必要な
ドライバー DLL を、exe と同じフォルダーに置く必要があります。プログラムはアーキテクチャに
応じて対応ファイルを自動で読み込みます（`wintun-amd64.dll` / `wintun-x86.dll` /
`wintun-arm64.dll`）— **リネーム不要**で、下表のとおり置くだけです:

| exe | 対応するドライバー DLL |
| --- | --- |
| `wireguideplus-amd64.exe`（64ビット） | `wintun-amd64.dll` |
| `wireguideplus-x86.exe`（32ビット） | `wintun-x86.dll` |
| `wireguideplus-arm64.exe`（ARM64） | `wintun-arm64.dll` |

ドライバー DLL は `wintun-0.14.1.zip` に含まれます（
[docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#42-wintun-driver-dll) を参照）。リリースでは
`wireguideplus-<version>-amd64-portable.zip` / `wireguideplus-<version>-x86-portable.zip` /
`wireguideplus-<version>-arm64-portable.zip` のポータブル zip も提供しています。各 zip には
exe と対応するドライバー DLL が**同梱**されており、解凍するだけで実行できます。
リリースで個別 DLL の添付は廃止しました（ポータブル zip またはインストーラーを
ご利用ください）。対応するドライバー DLL が exe の隣にない場合、トンネルを作成できません。



### macOS（Apple Silicon）

リリースごとに 2 種類のアーティファクトを提供しています：

- `WireGuidePlus-<version>-darwin-arm64.dmg` — アプリケーションフォルダへドラッグするインストーラー。
- `WireGuidePlus-<version>-darwin-arm64.zip` — ポータブル `.app` バンドル。

`.dmg` を開き、**WireGuide Plus** を「アプリケーション」へドラッグし、Spotlight または Launchpad から起動します。ポータブル `.zip` は展開すると `wireguideplus.app` になり、そのまま実行できます。

注意：

- **Apple Silicon のみ。** CI は `arm64` の単一アーティファクトをビルドします。Intel Mac は[ソースからビルド](docs/DEVELOPMENT.md)する必要があります。
- **Ad-hoc 署名のみ（Notarization なし）。** 初回起動時に macOS Gatekeeper が警告します。右クリック → **開く**、または次のコマンドで隔離属性を一度クリアしてください：
  ```sh
  xattr -dr com.apple.quarantine /Applications/wireguideplus.app
  ```
- arm64 ビルドの Homebrew cask も提供しています — `brew install --cask wireguideplus` でも同じ `WireGuidePlus-<version>-darwin-arm64.zip` を取得できます。
- **位置情報サービスの許可（SSID ごとの自動化用）。** SSID ごとの自動接続は現在の Wi-Fi SSID を読み取りますが、macOS ではこれに **位置情報サービス** の権限が必要です。**システム設定 → プライバシーとセキュリティ → 位置情報サービス** で許可（まず総スイッチを入れ、次に WireGuide Plus を許可）してください。ない場合、SSID 条件を評価できず SSID ベースのルールは発動しません。

### Linux（実験的）

各アーキテクチャ（`amd64`、`arm64`）ごとに 2 種類のアーティファクトを提供しています：

- `WireGuidePlus-<version>-linux-<arch>.deb` — Debian / Ubuntu インストーラー。
- `WireGuidePlus-<version>-linux-<arch>-portable.tar.gz` — ポータブルバイナリ。

`.deb` はパッケージマネージャーでインストールします（例：
`sudo apt install ./WireGuidePlus-<version>-linux-amd64.deb`）。ポータブル tarball は展開して
`./wireguideplus` を実行します。ポータブル版には GTK3 / WebKitGTK ランタイムが必要です
（`.deb` は自動でインストールします）。最小構成のシステムでは先にインストールしてください：

```sh
sudo apt-get install -y libgtk-3-0 libwebkit2gtk-4.1-0 libayatana-appindicator3-1
```

> Linux ビルドは**実験的**です — CI でのビルドのみで実機テストはまだ行われておらず、
> デスクトップセッションが必要です（ヘッドレスサーバーには非対応）。

## コード署名

コード署名はプラットフォームごとに異なります。**Windows** では公開されるすべての**インストーラー**に Authenticode 署名（SignPath 署名が有効な場合）が施され、**整合性**（署名後に改ざんされていないこと）を検証でき、初回実行時の SmartScreen 警告も減ります。**macOS** では `.app` は**Ad-hoc 署名のみ**（Apple 開発者署名なし）のため、初回起動時に Gatekeeper が警告します（macOS インストール手順を参照）。**Linux** の `.deb` とポータブル版は**未署名**です。

署名が証明するのは**誰が署名したか**であり、それ単体では**インストーラーがどのように
ビルドされたか**までは証明しません。ビルドの出所、承認ワークフロー、アカウント
セキュリティ、再現性、および各リリースに同梱される SHA-256 チェックサムについては
[SIGNING-POLICY.md](SIGNING-POLICY.md) に記載しています。

注: すべてのプラットフォームでコード署名があるのは Windows インストーラーのみです。macOS の `.app` は Ad-hoc 署名、Linux のアーティファクトは未署名のため、各リリースに同梱される Ed25519 署名付き `SHA256SUMS` が汎用的な整合性チェックとなります。

> Free code signing provided by [SignPath.io](https://signpath.io), certificate by
> [SignPath Foundation](https://signpath.org).

## アンインストール

- **Windows** — **コントロールパネル → プログラムと機能 → WireGuide Plus** からアンインストールするか、インストール先のアンインストーラーを実行します。
- **macOS** — **WireGuide Plus** を「アプリケーション」からゴミ箱へドラッグします。必要に応じて `~/Library/Application Support/wireguideplus` と `~/Library/Preferences/com.imonior.wireguide-plus.plist` も削除してください。
- **Linux** — `sudo apt remove wireguideplus`（`.deb`）、またはポータブルバイナリと `~/.config/wireguideplus` を削除します。
